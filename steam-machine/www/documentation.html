Steam Machine (System Bridge)

Controls a Steam Machine or any SteamOS/Linux PC running System Bridge v5 (https://system-bridge.timmo.dev/). Power on is via Wake-on-LAN; everything else goes over the System Bridge WebSocket API on port 9170.

Steam Machine setup (once)

  1. Install System Bridge v5 on the Steam Machine (Flatpak recommended on SteamOS, or the AUR package / binary + a user systemd service so it survives SteamOS updates).
  2. Make sure it starts automatically and runs in the background.
  3. Get the API token: run system-bridge client token on the machine (or read ~/.local/share/system-bridge/v5/token).
  4. Enable Wake-on-LAN in BIOS/firmware settings if you want power-on from Control4.

Composer setup

  1. Connections > Network: enter the Steam Machine's IP address (reserve it in DHCP).
  2. Connections > Control/AV: bind HDMI OUT (and optionally AUDIO OUT) to your display/AVR.
  3. Properties: paste the System Bridge Token. Set Launch Into Big Picture and Off Mode (Sleep or Power Off) as desired.
  4. Actions tab: use "Get MAC Address From Steam Machine" to fill the MAC automatically, and "Send Test Notification" / "Test Connection" to verify the link.

Game mini apps

Add one "Steam Game (Mini App)" driver per game, set its Game Name and Steam App ID (steamdb.info), then in Connections bind the mini app's "Steam Game" RF_MINI_APP output to a free "Game App N" input on this driver. The game then appears in the room's Watch list and launches via its steam:// URI when selected.

Notes and limitations

  • Transport keys map to System Bridge media control (MPRIS/playerctl) - they control media players (browser, Spotify, etc.), not the running game.
  • D-pad/Enter/Back keys use keyboard injection, which works in Desktop Mode but may not work inside the SteamOS game session (gamescope/Wayland). Game launching via steam:// URIs works everywhere and is the recommended control path.
  • "Notification Sent" fires when Control4 successfully delivers a notification to the machine; System Bridge does not report notifications from other sources.
  • Sleep/Shutdown require System Bridge to be reachable; Wake-on-LAN requires the MAC address property and LAN (not WiFi) connectivity.
