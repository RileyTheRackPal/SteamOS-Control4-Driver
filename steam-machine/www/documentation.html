Steam Machine (System Bridge)

Controls a Steam Machine or any SteamOS/Linux PC running System Bridge v5 (https://system-bridge.timmo.dev/). Power on is via Wake-on-LAN; everything else goes over the System Bridge WebSocket API on port 9170.

Steam Machine setup (once)

  1. Install System Bridge v5 on the Steam Machine (Flatpak recommended on SteamOS, or the AUR package / binary + a user systemd service so it survives SteamOS updates).
  2. Make sure it starts automatically and runs in the background.
  3. Get the API token: run system-bridge client token on the machine (or read ~/.local/share/system-bridge/v5/token).
  4. Enable Wake-on-LAN in BIOS/firmware settings if you want power-on from Control4.

Composer setup

  1. Connections > Network: enter the Steam Machine's IP address (reserve it in DHCP).
  2. Connections > Control/AV: bind HDMI OUT (and optionally AUDIO OUT) to your display/AVR.
  3. Properties: paste the System Bridge Token. Set Launch Into Big Picture and Off Mode (Sleep or Power Off) as desired.
  4. Actions tab: use "Get MAC Address From Steam Machine" to fill the MAC automatically, and "Send Test Notification" / "Test Connection" to verify the link.

Game mini apps

Add one "Steam Game (Mini App)" driver per game, set its Game Name and Steam App ID (steamdb.info), then in Connections bind the mini app's "Steam Game" RF_MINI_APP output to a free "Game App N" input on this driver. The game then appears in the room's Watch list and launches via its steam:// URI when selected.

Colored (RGBY) navigator buttons

Control4's colored remote/touchscreen buttons are physical programmable buttons — Control4 does not auto-route them to the driver. To use them: in Composer, program the navigator's red/green/yellow/blue button to execute the matching command (Red Button, …). Each button's behavior is chosen by a property dropdown (System Design → Red/Green/Yellow/Blue Button Action): Steam Menu, Quick Access Menu, Toggle On-Screen Keyboard, Screenshot, Toggle Magnifier, Force Quit Game, Launch Big Picture, Media Play/Pause, or Fire Programming Event (fires the matching event so you can bind any Control4 programming). The Steam Menu and chord actions require the c4pad Gamepad Bridge; Launch Big Picture and Media Play/Pause do not. The individual Steam actions are also standalone commands, bindable to any button or scene.

Security & privacy (read before deploying)

The System Bridge token is a full local-user credential - it grants arbitrary file reads, shutdown/restart, opening URIs, keyboard injection, and command execution on the Steam Machine. System Bridge transmits it in cleartext over ws:// (no TLS) and accepts connections from any origin.

Encrypt it: install the c4tls proxy (steamos-tls in the driver package) on the Steam Machine and set the Connection Security property to "TLS encrypt-only" (stops passive sniffing) or "TLS pinned" (also stops active MITM; paste the cert the installer prints into the Server Certificate property). Also compensate at the network layer:

  • Put the Steam Machine and the Control4 Director on a dedicated/trusted VLAN.
  • Firewall port 9170 (and the TLS port) so only the Director's IP can reach it; never port-forward it. A router/switch ACL is more durable than a host firewall.
  • Prefer wired Ethernet; rotate the token (system-bridge client token) if exposed.

Token at rest: the token is NOT kept in a cleartext property - on entry it is moved into Director's encrypted PersistData store and the field is cleared (see the Token Status property and the Clear Stored Token action). Driver encryption is optional and only protects the Lua source, not the stored token. Still avoid sharing project backups taken with a real token configured.

Privacy: uptime, CPU/GPU temperature, usage, hostname, MAC, and now-playing are pulled from System Bridge; hostname/now-playing/current-game persist in Control4 variables (and thus in the Director DB and backups). The driver only sends steam:// URIs to the machine (other schemes are rejected) and sanitizes incoming data. Full threat model: see SECURITY.md in the driver package repository.

Notes and limitations

  • Transport keys map to System Bridge media control (MPRIS/playerctl) - they control media players (browser, Spotify, etc.), not the running game.
  • With the default Keyboard backend, D-pad/Enter/Back use keyboard injection, which works in Desktop Mode but may not reach the SteamOS game session (gamescope/Wayland). For full game-mode control, install the c4pad Gamepad Bridge on the Steam Machine (see the steamos-pad folder in the driver package repository: a virtual Xbox 360 controller with no network listener, driven through System Bridge's command allowlist) and set the Nav Input Backend property to "Gamepad Bridge". D-pad then acts as a real controller in Big Picture and in games, with Enter=A, Back=B, Menu=Start, Guide=Steam button.
  • "Notification Sent" fires when Control4 successfully delivers a notification to the machine; System Bridge does not report notifications from other sources.
  • Sleep/Shutdown require System Bridge to be reachable; Wake-on-LAN requires the MAC address property and LAN (not WiFi) connectivity.
  • Media Volume Up/Down/Mute act on the active MPRIS media player (browser/Spotify), not system or game audio; Mute is one-way (recover with Media Volume Up).
  • With Off Mode = Power Off, picking a game while the machine is off wakes it, but if a cold boot takes longer than 5 minutes the queued launch is dropped (Sleep mode resumes in seconds and is recommended).
